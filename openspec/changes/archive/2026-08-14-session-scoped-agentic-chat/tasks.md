## 2. Convert `agenticChatProvider` to a family

- [x] 2.1 Change `agenticChatProvider` to `NotifierProvider.autoDispose.family<AgenticChatNotifier, AgenticChatState, String>`. Note: this Riverpod version (3.0.3) routes the family arg through the notifier's constructor, not a `build(arg)` parameter — `AgenticChatNotifier(this.sessionId)` + zero-arg `build()`, not `build(String sessionId)` as originally phrased; same outcome (`sessionId` available as a field, `ref.read(settingsProvider).agenticSessionId` lookups dropped).
- [x] 2.2 Implement the two-part `ref.keepAlive()` logic from design Decision 3. Note: implemented via `ref.onCancel`/`ref.onResume` (arm the linger only when the last watcher actually drops, cancel it on resume) plus an overridden `state` setter (in place of `ref.listenSelf`, which isn't reachable from a hand-written Notifier in this Riverpod version — it's codegen-only) for the isAwaiting-gated indefinite hold.
- [x] 2.3 Add a seeding method (mirrors the existing `setStateForTest` pattern) used by the new-session flow (Section 4) to populate a freshly-created session's family instance with its first exchange.
- [x] 2.4 Add `refreshFromServer()` on `AgenticChatNotifier` per design Decision 5: computes `afterMessageId` from the last known final message (or `null`) and calls the existing fetch-and-merge logic — the single entry point that replaces separately calling `loadHistory()` with no arguments.
- [x] 2.5 Remove the seven now-structurally-unnecessary staleness guards (`_dispatchUserMessage` success/error, `loadHistory` incremental branch, `stopCycle`, `triggerContinuation` success/error, `grantApproval` error) and the transient-state-reset listener in `build()` — each guard's job is now done by family isolation instead. Also removed `clearChat()`/`clearMessages()` (no longer meaningful on a per-session notifier — see `purgeSession()` and the engine-URL-change handling in `settings_provider.dart`, Section 4).

## 5. SSE routing

- [x] 5.1 `sse_provider.dart`'s `MessagesAppendedEvent` handler: resolve `agenticChatProvider(event.sessionId)` and route to it directly, guarded by `ref.exists(...)` per design Decision 4, instead of comparing to a single active-session id.
- [x] 5.2 Point `fetchSinceCursor()`'s cursor-computation logic at the Section 2.4 `refreshFromServer()` method on the target instance. Note: the coalescing behavior `fetchSinceCursor()` used to provide (don't fire overlapping requests for rapid-fire events) moved onto `refreshFromServer()` itself rather than staying SSE-specific — every caller (switch, resume, SSE) benefits, not just SSE. `fetchSinceCursor()` is deleted; `sse_provider.dart` calls `refreshFromServer()` directly.
- [x] 5.3 Confirm (per design Decision 4) `SessionCreatedEvent`/`SessionUpdatedEvent` handlers need no change beyond reading `displayedSessionProvider` instead of `settings.agenticSessionId` — verified they still only touch `sessionsProvider` directly, not through `agenticChatProvider`'s message state.
- [x] 5.4 `sse_client.dart`: add `createdAt` (parsed from the event envelope's existing `created_at`) to the `SseEvent` base class so all event types expose it, per design Decision 4.
- [x] 5.5 `sessions_provider.dart`: add a lightweight `bumpActivity(sessionId, timestamp)` method — updates the matching `SessionListItem`'s timestamp and reorders it to the top, without touching `title`/other fields, no-ops if the session isn't currently in the list, and no-ops if `timestamp` is not strictly newer than what's already shown (per design's out-of-order-event risk mitigation).
- [x] 5.6 Wire the `MessagesAppendedEvent` handler's `ref.exists(...)` == false branch to call `bumpActivity(event.sessionId, event.createdAt)` instead of just logging and dropping the event.

## 6. Test migration

- [x] 6.1 Mechanical pass over `agentic_chat_provider_test.dart`: `agenticChatProvider.notifier` → `agenticChatProvider(sessionId).notifier` for all ~40 existing tests. Also dropped the now-unused `sessionId` param from `_StubSettingsNotifier`/`_makeContainer` (session identity is the family key now, not Settings), and added `.catchError((_) {})` to a few previously-unawaited `declineApproval()` calls that now always attempt a real network call (no more `if (sessionId == null) return;` short-circuit — sessionId is always real in a family instance) and would otherwise surface as unhandled zone errors.
- [x] 6.2 Deleted the `session switch race` group (its guards no longer exist) and the `_sessionSwitchingClient` helper; replaced by the isolation/disposal tests in 6.4.
- [x] 6.3 Reworked `message_event_dedup_test.dart`: its original purpose (testing `fetchSinceCursor()`'s coalescing) is obsolete — that logic moved into `AgenticChatNotifier.refreshFromServer()` and is covered in `agentic_chat_provider_test.dart`. Repurposed the file to test `SseNotifier`'s new routing decision instead (also covers most of 6.7): routes to an existing instance's `refreshFromServer()`; never instantiates a new instance for `messages.appended` on a session with none live; bumps `sessionsProvider`'s activity/ordering for that case; an out-of-order `created_at` doesn't regress an already-newer timestamp. Added `SseNotifier.handleEventForTest()` (`@visibleForTesting`) to drive `_handleEvent` directly, matching the existing `setStateForTest`/`ingestMessagesForTest` pattern.
- [x] 6.4 Added a `per-session isolation` group (two session ids produce independent instances) and a `disposal policy` group (in-flight survives being unwatched; idle survives a quick flip back within the linger window; idle is disposed and rebuilds fresh past the linger window if never rewatched). Found and fixed two real bugs along the way: (1) `ref.keepAlive()`/`state` access is disallowed synchronously inside `onCancel`/`onResume`/`onDispose` in this Riverpod version (3.3.2) despite doc comments suggesting otherwise — fixed by deferring to `scheduleMicrotask` + `ref.mounted` check; (2) every async method needed a `ref.mounted` guard after its last `await` (only `isLoading`-setting methods were protected by the keepAlive-while-awaiting logic) — added throughout, including in `refreshFromServer`'s coalesced re-fetch, which also wasn't threading `client` through recursively (a real bug the coalescing test caught).
- [x] 6.5 Covered by `new_chat_draft_provider_test.dart` (see 1.3): draft state before/during creation, correct seeding of the family instance and `displayedSessionProvider` after creation, draft reset on success.
- [x] 6.6 Covered by the `disposal policy` group in `agentic_chat_provider_test.dart` (see 6.4): redisplaying within the idle-linger window keeps the existing state (no rebuild); redisplaying a genuinely disposed instance starts fresh. The "external append visible without a full reload" half is covered in spirit by `message_event_dedup_test.dart`'s "routes to an existing instance's `refreshFromServer()`" test — a kept-alive/lingering instance is exactly such an existing instance.
- [x] 6.7 Covered by 6.3's `message_event_dedup_test.dart` rework (end-to-end via SSE) plus a new `sessions_provider_test.dart` (new file — none existed before) exercising `bumpActivity` directly: reorders to the top with multiple sessions present, updates only the timestamp, preserves `isActive`, no-ops for an unknown session, and no-ops for a non-newer timestamp.
